# Protocol. Android-каркас

**Реальный конфиг и логи в репозиторий не попадают никогда.** Здесь только
`../config.example.json` с выдуманными данными. `.gitignore` и локальный
pre-commit хук блокируют остальные `config*.json`, `*.log` и `blockers*`.
Реальный конфиг живёт только на телефоне в `Documents/Protocol/`.

Каркас по `../SPEC.md`. Kotlin, minSdk 26, targetSdk 34, без сети.

## Состояние

Собирается в GitHub Actions (`.github/workflows/build.yml`): при каждом
пуше в `main` прогоняются юнит-тесты движка и собирается debug APK.
Готовый APK лежит в скользящем пре-релизе
https://github.com/linux100talion/protocol/releases/tag/latest-debug
На телефоне (Motorola, Android 15) приложение установлено и запущено
30.10.2026, пример конфига прошёл проверку.

Что есть:

- `config/` модель, разбор JSON (`org.json`), все проверки из SPEC 4.6.
- `engine/` состояние и правила: цикл, шаги, дерево, повторы, эскалация,
  таймаут, причина блокера, процессы с `wait` и паузой. Чистый Kotlin,
  покрыт юнит-тестами в `app/src/test`.
- `service/ReminderService` foreground-сервис: владеет движком, таймеры
  под wakelock, будильник `setAlarmClock` как страховка, уведомления.
- `receiver/` будильник, загрузка, смена времени, кнопки уведомлений.
- `ui/` главный экран с карточками открытых процессов, экран шага (без
  «назад», поверх блокировки), экран «остановлена», просмотр логов с
  «Поделиться». `ScreenBinder` рисует кнопки по типу узла для обоих.
- `log/EventLog` текстовый лог и журнал блокеров.

Что сознательно отложено (TODO в коде):

- Логи пишутся в `Android/data/com.protocol/files/Protocol/`, а не в
  `Documents/Protocol/`. Перенос через MediaStore.
- База данных (SPEC 7.4). Текстовые файлы первичны, база не обязательна.
- Инструкция для прошивок с убийством фона (Xiaomi, Huawei, Samsung).
- Иконка приложения: временная, из векторного колокольчика.

## Сборка локально

Нужны JDK 17 и Android SDK (platform 34, build-tools 34). Варианты:

1. **Компьютер с Android Studio.** Открыть папку `android/`, Studio сам
   подтянет Gradle 8.7 и SDK. Build > Build APK.
2. **Командная строка на ПК.**
   ```
   cd android
   gradle wrapper --gradle-version 8.7     # один раз, создаст gradlew
   ./gradlew test                          # юнит-тесты движка
   ./gradlew assembleDebug                 # APK в app/build/outputs/apk/debug/
   ```
3. **Внутри proot на телефоне.** Возможно, но медленно, и для arm64 нужен
   пересобранный `aapt2`. Не рекомендуется для первой сборки.

Файла `gradlew` в репозитории нет, его создаёт команда `gradle wrapper`
или Android Studio.

## Установка на телефон

1. Разрешить установку из неизвестных источников, поставить APK.
2. Положить `config.json` в `Documents/Protocol/` (пример:
   `../config.example.json`).
3. В приложении: «Выбрать конфиг», «Проверить конфиг», «Запустить».
   При первом запуске приложение по очереди попросит: уведомления, точные
   будильники, исключение из оптимизации батареи, полноэкранные уведомления.
   После каждого разрешения нажать «Запустить» снова.

## Ключ подписи debug-сборок

Actions подписывает APK постоянным ключом из секретов репозитория
`DEBUG_KEYSTORE_B64` (PKCS12 в base64, alias `protocol`) и
`DEBUG_KEYSTORE_PASSWORD`. Без одного ключа каждая сборка получала бы
случайный сертификат, и Android отказывался бы ставить обновление поверх
старой версии («Приложение не установлено»). Сам ключ лежит вне репозитория,
на телефоне в `~/.protocol-keys/`. Потеря ключа означает переустановку
приложения с потерей состояния движка и логов в `Android/data`.
